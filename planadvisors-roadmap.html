PlanAdvisors Platform Roadmap

Approved 27 Sep 2026 5 phases · ~12 weeks Razorpay · Surepass · MSG91

00 Overview

PlanAdvisors is expanding from an AI travel assistant into a trust-based travel marketplace. The core platform — FastAPI WebSocket backend, Next.js 16 frontend, Claude tool-calling — already exists. This roadmap adds the commercial and trust layer on top.

What already works: AI chat (30+ tools), packages/tickets/visa CRUD, explore marketplace, agent registration with partial phone OTP, enquiry modal, admin stats dashboard.
What this plan adds: Aadhaar + travel-license verification, Razorpay subscriptions, real-time agent↔traveller chat, admin approval queue, API usage tracking, free-tier limits, agent-lead matching, document requirements tool.

01 User Roles

Three roles share a single OAuth login (Google / GitHub). An agent is also a traveller — same account, both AI chat and listing management available.

🧳 Traveller
Any logged-in user. AI chat, browse marketplace, contact agents, plan trips.
Default on login
🏢 Travel Agent (Travels)
Register → verify identity → admin approves. Create packages, tickets, visa. Chat with travellers.
Requires approval
⚙️ Admin
Email in ADMIN_EMAILS env var. Approve agents, manage subscriptions, view all analytics.
Env-var gated

Selected at registration — drives which create forms appear and how the public profile is shown:

02 Agent Registration & Verification

Agents must complete a 5-step verification flow before they can publish listings. Every step must pass before the admin review queue is triggered.

1
Basic Info
Name, agency type, phone, location, specializations, languages, years of experience, services offered (multi-select).
Already built
2
Phone OTP
6-digit OTP sent via MSG91 SMS to the registered phone. Verified OTP sets phone_verified = true. ENV: MSG91_AUTH_KEY.
Backend exists — SMS not wired
3
Aadhaar OTP Verification
Agent enters their 12-digit Aadhaar number. Backend calls Surepass API → UIDAI sends OTP to the Aadhaar-linked mobile. Agent enters OTP to verify. Only the last 4 digits are stored. Cost: ~₹5–10/verification. ENV: SUREPASS_API_KEY.
New
4
Travel License Upload (agency agents only)
Tour operators / agencies upload their travel license (PDF or image). Stored in Azure Blob Storage. Individual agents skip this step. ENVs: AZURE_STORAGE_ACCOUNT, AZURE_STORAGE_CONTAINER.
New
5
Admin Review & Approval
Agent enters pending_review state. Admin sees them in the Approval Queue with all verification badges. Admin approves (email + SMS sent to agent) or rejects with a reason. Only approved agents' listings appear publicly.
New

New AgentProfile fields

03 Subscription Model

Monthly recurring billing via Razorpay Subscriptions API. Both agent and traveller plans are ₹50/month. Webhooks update DB on payment events.

Agent tiers

Free
₹0 /month
  • Max 10 tour packages
  • Max 10 ticket listings
  • Max 5 visa services
  • 5 AI draft generations / month
  • No real-time chat
  • No enquiry notifications
  • Standard search ranking
Pro
₹50 /month
  • Unlimited packages, tickets, visa
  • Unlimited AI draft generation
  • Real-time chat with travellers
  • SMS + email enquiry notifications
  • Priority listing in search results
  • Receive search leads from travellers

Traveller tiers

Free
₹0 /month
  • Full AI travel assistant
  • Browse marketplace
  • Contact via WhatsApp / email
  • No real-time agent chat
  • No agent lead matching
  • No priority responses
Pro
₹50 /month
  • All Free features
  • Real-time chat with agents
  • Search signals shared with relevant agents (with consent)
  • Agents proactively contact you with offers
  • Priority agent responses
Privacy: Search sharing requires explicit consent during Pro onboarding. The privacy policy must disclose that search preferences are shared with relevant agents to help find better deals — no other use.

New endpoints

POST /api/subscription/create    -- create Razorpay order, return checkout data
POST /api/subscription/webhook   -- verify HMAC signature, update DB on payment events
GET  /api/subscription/status    -- current plan for calling user
POST /api/subscription/cancel    -- cancel recurring subscription

05 Traveller Features

Document requirements tool New

New Claude tool get_document_requirements(trip_type, nationality, destination). Returns what's needed for domestic flight / international flight / hotel check-in. No external API needed — a structured knowledge base in services/documents.py.

ContextDocuments
Domestic flight (India)Aadhaar, PAN, Passport, or Voter ID — any government-issued ID
International flightPassport (≥6 months validity), visa, travel insurance
Hotel in IndiaAadhaar or Passport copy for guest registration
Hotel abroadPassport copy

Visa guidance

When a traveller searches for an international destination, the chat proactively shows: visa-on-arrival vs tourist visa required, agents who handle that country's visa (pulled from visa_services table), and a self-service step-by-step guide if the traveller prefers to apply independently.

Agent matching on search Pro travellers only

When a Pro traveller's chat signals travel intent, the backend extracts structured intent and notifies matching agents. Agents can proactively reach out via the direct chat system.

search_leads (id, traveller_email, search_intent JSON, matched_agents JSON, created_at)
-- search_intent: {type, destination, dates, budget, travelers}

Traveller profile page New route: /profile

Currently there is no profile page for travellers. Add: home city, nationality, travel style, currency, passport expiry, subscription status + upgrade button, search-sharing consent toggle.

07 Marketplace & Chat Boundary

Listing visibility rules

A listing is publicly visible only when: agent approval_status = 'approved' AND is_active = true, AND listing is_public = true AND status = 'published'. Currently the explore API does not check approval status — that filter needs to be added.

Search ranking

Pro agent listings are ranked first. Within the same tier, order by views_count then created_at (freshness). This creates a clear upgrade incentive without hiding free agents entirely.

Chat-to-agent handoff

When Claude detects a traveller looking for something an agent can help with, it surfaces a contextual prompt:

"I found 3 local agents who specialise in Dubai family packages. Would you like to browse them? → View Agents"

Chat boundary (travel-focused)

The AI currently has no topic guard. Add a clause to the Claude system prompt in services/claude.py that redirects off-topic queries:

"If the user asks about topics unrelated to travel (cooking, coding, politics, etc.),
respond: 'I'm PlanAdvisors, your travel planning assistant! I can help you plan
trips, find flights, hotels, and connect with verified travel agents. Are you
planning a trip?'

If the query is ambiguous — a 'trip to hospital' or a 'factory tour' — ask:
'Just to check — are you looking to plan a travel trip?'"

This is a single prompt change in backend/services/claude.py — no code refactor needed.
